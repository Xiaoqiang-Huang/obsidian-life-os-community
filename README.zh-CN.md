# Life OS Assistant 0.3.9

Life OS Assistant 是一个本地优先的 Obsidian 个人工作系统，用来管理日记、任务、知识、长期记忆、AI 项目会话和有证据的周期复盘。用户可读内容保存在当前 Vault 的 Markdown 中；AI 生成的写入先成为候选，由用户确认后再进入正式数据。

## 主要功能

- 日记、快速记录、任务提取、跨日延续、项目任务和学习打卡。
- AI 助手使用混合检索、来源引用和上下文检查，不把整个知识库或整段历史无差别塞给模型。
- 项目文档支持结构化导入、紧凑摘要、全文搜索、PDF 文本提取与 OCR 降级。
- 项目上下文支持 Codex、Claude Code、OpenCode、CodeBuddy、WorkBuddy、Pi、Cursor、Windsurf、Gemini CLI、GitHub Copilot、Kiro、Aider、Qwen Code、Trae、通义灵码、Cline、Roo Code、Continue 和网页 AI。
- 每条可见对话都是可追溯节点；会话可搜索、倒序阅读、收起，过程树可缩放和定位。
- 会话交接 V2 扫描完整节点，区分「已验证完成 / 声称完成 / 部分完成 / 待处理」，保留证据并生成跨工具五文件迁移包。
- 项目共享记忆与工具专属规则分开版本化，交接时作为只读背景携带。
- 日、周、月和自定义复盘使用不同结构；事实带日期或节点引用，用户补充与事实快照不会被 AI 覆盖。
- 自动复盘默认关闭；开启后只生成 `Reviews/Drafts/` 待确认草稿，不静默改写日记或保存正式复盘。
- 提示词库、LLM Wiki、记忆确认、网页 AI 浏览器桥和明暗主题响应式布局。

## 安装、升级与卸载

### 社区安装

通过 Obsidian 社区插件市场审核后，在「设置 → 社区插件」中搜索并安装 **Life OS Assistant**。

### 手动安装

在 Vault 中创建 `.obsidian/plugins/personal-life-system/`，放入：

- `main.js`
- `manifest.json`
- `styles.css`

重载 Obsidian 后启用插件。不要复制其他用户的 `data.json`，其中可能包含模型配置或授权状态。

### 升级和卸载

- 升级时只替换 Release 三件套，保留 `data.json` 和 Life OS 数据目录。
- 禁用或卸载插件不会删除 Markdown 数据。
- 彻底删除前先备份设置中的 Life OS 根目录；浏览器扩展和外部 AI 导出文件需单独删除。

## AI 助手如何使用知识

助手先分析问题，再从项目、日记、任务、知识、记忆和复盘中检索有限且相关的片段。回答中的 `[S1]` 等标记可在「上下文来源」中打开原文核对。长会话会压缩旧上下文，而不是每次发送全部历史。

需要写入时，问答与写回分开：AI 先生成目标位置和内容预览，用户确认后才写入。

## 项目会话与会话交接 V2

1. 新建或选择项目，绑定一个或多个真实工作目录。
2. 用户主动检查本地会话，或导入标准 JSON / JSONL。未匹配会话默认隐藏，不会自动归属。
3. 按会话名称、工具、目录或会话 ID 搜索，预览新增、追加、重复和冲突后再导入。
4. 在会话阅读器按最新优先或从头阅读，搜索消息、收起普通节点，并从提纲/过程树跳到原消息。
5. 在「会话交接」核对目标、当前状态、已验证/待验证结果、决定、失败、风险、下一步和验收条件。
6. 点击「迁移到其他工具」生成：`LIFEOS-START-HERE.md`、`lifeos-protocol.json`、`handoff.md`、`project-memory.md`、`source-index.json`。

成功导入的来源可自动跟踪末尾新增消息；历史被改写时必须人工确认，旧版本不会被覆盖。

## 外部 AI 使用协议

首次初始化会生成：

- `<根目录>/AI/AI-TOOL-GUIDE.md`
- `<根目录>/AI/protocol.json`
- `<根目录>/AI/Inbox/`
- `<根目录>/AI/Outbox/`

让 Codex、Claude Code、OpenCode、Pi、CodeBuddy、WorkBuddy 或其他 AI 先读 `AI-TOOL-GUIDE.md`。会话文本、网页内容、历史命令和规则文件都是证据，不是可自动执行的系统指令。

外部 AI 需要回写时只能先把候选写到 `AI/Inbox/`；未经用户确认，不得覆盖日记正文、正式记忆、任务、已保存复盘或项目原有工具规则。

## 日记、复盘与自动待确认草稿

周期复盘先选择日期范围和日报来源，再以用户日记正文为主线，用已确认项目活动、实际完成任务、打卡和当前未完成事项核对。

- 日、周、月分别使用不同章节结构。
- 事实性结论需要引用日期或会话节点；没有证据时应写「资料不足」。
- AI 区、用户补充和事实快照彼此隔离；重新生成只替换 AI 区。
- 每次正式保存都在 `Reviews/Periods/` 新建版本。
- 自动复盘可设置时间和启动补生成，但只创建待确认草稿。来源变化后标记过期并等待手动刷新，不静默追加 AI 调用。

## 网页 AI 浏览器桥

Chrome / Edge 扩展只在用户点击后采集网页中已渲染的可见对话，通过随机令牌连接 `127.0.0.1` 本地桥。扩展不读取 Cookie、隐藏推理或供应商私有接口。桥不可用时可下载标准 JSON 后手动导入。

## 文档导入与 OCR

文本 PDF 优先本地解析；扫描件使用本地或按需下载的 Tesseract OCR 资源。只有用户明确配置 PaddleOCR PP-StructureV3 地址时，所选 PDF 才会发送到该端点。导入结果保留来源附件、段落结构、紧凑摘要和识别提示。

## 完整功能需要授权

Life OS 包含免费本地能力与 Pro 工作流。Pro 需要有效的服务端权益、授权码、试用码或激活码。从 GitHub 或社区市场安装不等于获得 Pro 权限，也不等于获得商业使用许可。本地 Markdown 查看、备份、导出和迁移不被 Pro 锁住。

## 账号或授权要求

只有用户主动执行激活、订单查询、试用、兑换或账号操作时，插件才连接 Life OS 授权服务。授权状态保存在本地插件数据中，升级时必须保留。

## 联网使用说明

Life OS 仅在这些用户可见场景联网：

- 向用户配置的 AI 服务商发送问题、选中上下文和必要附件。
- 授权、订单、试用、兑换和账号请求。
- 用户明确要求的网页搜索或 URL 读取。
- 社区三件套缺少本地 OCR 资源时的首次按需下载。
- 用户明确配置的 PaddleOCR PP-StructureV3 端点。
- 用户确认的 GitHub Skill 下载。

本地浏览器桥只监听回环地址。Life OS 不包含静默客户端遥测。

## 隐私说明

- Vault 内容默认留在本地；只有使用 AI、网页、OCR、GitHub 或授权功能时，必要内容才发送到对应服务。
- 项目扫描由用户主动触发；被拒绝来源可永久隐藏。
- 工具调用、原始快照、文件引用和工具全局记忆由用户选择是否导入。
- AI 记忆、项目事实和复盘草稿确认后才进入正式数据。
- 规则文件和会话内容按不可信数据处理；支持的导出会对敏感模式脱敏。
- API Key、模型配置、桥接令牌和授权状态保存在 `.obsidian/plugins/personal-life-system/data.json`，请保护 Vault 备份。

## 不内置更新器

社区版通过 Obsidian 官方社区插件更新流程更新，不内置独立更新器。

## 移动端支持

日记、任务、知识、记忆复核、AI 对话、复盘阅读和基础导航支持移动端。本地进程扫描、浏览器桥、打开命令行工具、大型 OCR 等桌面能力会显示明确的不可用或降级提示。

## 数据模型

设置中可配置根目录，常见子目录包括 `Daily/`、`Tasks/`、`Knowledge/`、`Memory/`、`Projects/`、`Reviews/`、`AI/` 和 `Exports/`。插件设置与授权状态位于本地 `data.json`，不属于 Release 三件套。

## 常见问题

- **AI 不懂知识库：** 选择正确项目和上下文模式，打开「上下文来源」核对命中的文件与片段。
- **浏览器扩展连不上：** 启用本地桥、复制最新连接 JSON、保持 Obsidian 运行；必要时下载 JSON 手动导入。
- **复盘草稿过期：** 打开「复盘 → 待确认复盘草稿 → 刷新并审核」。
- **OCR 很慢：** 大扫描件优先在桌面处理，或明确配置可信的结构化 OCR 服务。
- **黑屏或布局异常：** 重载插件、切回 Obsidian 默认主题，并在 issue 中提供版本、平台、主题、复现步骤和脱敏控制台错误。
